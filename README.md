# Flowers Classification

Модель классификации цветов на основе Vision Transformer (DeiT-Tiny).

Используемые библиотеки и технологии:

 `Pytorch` `Transformers` `ViT` `FastAPI` `Celery` `Reddis` `PostgreSQL` `Docker`
 `telegram-bot`

---

## Используемая модель `DeiT-Tiny`

В проекте использована предобученная модель:

* `"facebook/deit-tiny-patch16-224"`
* Размер входного изображения: **224×224**
* Предобучена на **ImageNet-1k**

Модель относится к архитектуре Vision Transformer (ViT) и была дообучена для задачи классификации 102 классов цветов.

---

## Данные

### Датасет

* Источник: [Oxford 102 Flower Dataset (Kaggle)](https://www.kaggle.com/datasets/yousefmohamed20/oxford-102-flower-dataset)
* Объем: ~8200 изображений
* Количество классов: 102
* Структура: изображения распределены по папкам, каждая папка соответствует отдельному классу цветка.

Датасет был:

* загружен с Kaggle
* преобразован в формат HuggingFace Datasets
* подготовлен для обучения через `Trainer`

---

## Аугментации

Из-за особенностей датасета (цветы чувствительны к цвету и форме) применялись умеренные аугментации.

Использовались:

* `RandomResizedCrop`
* `ColorJitter`
* `RandomHorizontalFlip`

Дополнительно:

* Изображения нормализованы в соответствии со стандартами ViT (`mean`, `std`)

---

## Разбиение данных

Датасет был предварительно разбит:

| Train | Validation | Test |
| ----- | ---------- | ---- |
| 12.5% | 12.5%      | 75%  |

Для борьбы с дисбалансом классов применён:

* `WeightedRandomSampler`

---

## Обучение модели

### Используемый фреймворк

Обучение проводилось с использованием `Trainer` из HuggingFace.

Дополнительно использовались:

* `EarlyStoppingCallback` — остановка обучения при отсутствии улучшения
* `CustomTrainer` — переопределён метод `get_train_dataloader()` для поддержки `sampler`

---

### Гиперпараметры

* Эпохи: 15
* Batch size:

  * Train: 32
  * Eval: 8
* Learning rate: 5e-5
* Weight decay: 0.001
* Модель сохраняется при наилучшем значении `eval_loss`

---

## Сохранение модели

После обучения модель сохраняется в локальную директорию со следующими файлами:

| Файл                       | Назначение                                                     |
| -------------------------- | -------------------------------------------------------------- |
| `config.json`              | Гиперпараметры модели                                          |
| `preprocessor_config.json` | Конфигурация процессора                                        |
| `model.safetensors`        | Веса модели                                                    |
| `metadata.json`            | Размеры изображений, список классов, отображение label ↔ class |

Данные файлы используются на FastAPI-сервере для инференса.

# Flower Classifier API


Сервер реализован на **FastAPI + Celery + Redis + PostgreSQL** с интеграцией Telegram-бота.

# Архитектура

## Технологический стек

* **FastAPI** — API-сервер
* **Celery** — асинхронная обработка задач
* **Redis** — брокер сообщений и backend результатов
* **PostgreSQL** — база данных
* **Docker / docker-compose** — контейнеризация
* **Telegram Bot API** — пользовательский интерфейс

---

# API (FastAPI + Celery)

## Основная логика работы

* `main.py`:

  * запускает FastAPI-приложение
  * инициализирует классификатор
  * запускает Telegram-бота
  * подключается к базе данных

* Все задачи по обработке изображений отправляются в очередь **Celery** и выполняются асинхронно.

* `tasks.py` (Celery Worker):

  * извлекает задачу из очереди
  * выполняет классификацию изображения
  * возвращает результат

---

## Redis + Celery

**Redis используется как:**

1. Брокер сообщений

   * принимает задачи от FastAPI
   * передаёт их Celery-воркеру

2. Backend результатов

   * хранит результаты выполнения задач

3. Кэш модели

   * сериализованная модель `FlowerClassifier` сохраняется в Redis (через `pickle`)
   * ускоряет повторную обработку без повторной загрузки модели

---

# Как происходит предсказание

1. Пользователь (через Telegram-бота) отправляет изображение цветка
2. FastAPI:

   * принимает фото
   * преобразует его в base64
   * формирует задачу Celery
3. Задача помещается в очередь Redis
4. Celery-воркер:

   * извлекает задачу
   * временно сохраняет изображение на диск
   * передаёт его в `FlowerClassifier.predict()`
5. Возвращается результат (топ-3 варианта с вероятностями)

## Доступные действия

После запуска бот предлагает две кнопки:

* Отправьте чёткое фото цветка
* Бот вернёт:

  * топ-3 варианта
  * точность предсказания

* Введите часть названия (например: `роза`, `подсолнух`)

* Получите фото и описание

# PostgreSQL

База данных содержит две основные таблицы:

---

# `users`

Хранит информацию о пользователях Telegram.

| Поле             | Описание                   |
| ---------------- | -------------------------- |
| telegram_user_id | Уникальный ID пользователя |
| username         | Никнейм пользователя       |

---

# `interactions`

Фиксирует все пользовательские запросы.

| Поле       | Описание                                           |
| ---------- | -------------------------------------------------- |
| user_id    | Внешний ключ → `telegram_user_id`                  |
| query_type | Тип запроса                                        |
| query_text | Текст запроса (если есть)                          |
| flower_image      | Бинарные данные изображения (если отправлено фото) |

### Возможные значения `query_type`:

* `define_by_photo`
* `search_by_name`
* `search_by_name_inline`

---

# Методы работы с БД

* `get_user_by_telegram_id` — получить пользователя
* `create_user` — зарегистрировать пользователя
* `save_query` — сохранить взаимодействие
