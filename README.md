# Flowers-Classification

---
### Модель **DeiT-Tiny**

Использовалось в проекте:

* `"facebook/deit-tiny-patch16-224"`
* Размер входа: 224x224
* Преобучена на ImageNet-1k
---
### Данные
* **Датасет на Kaggle**: [OxFord 102 Flower Dataset](https://www.kaggle.com/datasets/yousefmohamed20/oxford-102-flower-dataset)
* **Объем датасета**: Около 8200 изображений различных цветков
* **Структура**: Все изображения цветков распределены по папкам, которые по сути являются их классами.

Датасет был загружен и преобразован в формат HuggingFace Datasets

Примененные Аугментации:
В силу особенности датасета цветов нельзя применять сильные аугментации.
* `RandomResizedCrop`, `ColorJitter`, `RandomHorizontalFlip` для увеличения разнообразия обучающих примеров.
* Изображения нормализованы под стандарты ViT (`mean`, `std`)

Разбиение:

* Датасет заранее разбит на Train | Validation | Test = 12.5% | 12.5% | 75%
* Для борьбы с дисбалансом классов использован `WeightedRandomSampler`

---

### Обучение

* Использован `Trainer` из HuggingFace с:

  * `EarlyStoppingCallback` (остановка при отсутствии улучшения)
  * `CustomTrainer` с переопределением `get_train_dataloader()` для поддержки `sampler`
* Параметры:

  * Эпохи: 15
  * Batch size: 32 (train), 8 (eval)
  * Learning rate: 5e-5, weight decay: 0.001
  * Модель сохраняется при наилучшем `eval_loss`
 

*Получение самой модели:
Модель сохраняется в локальную директорию:
 * config.json - гиперпараметры модели
 * preprocessor_config.json - конфигурация процессора модели
 * model.safetensors - веса модели
 * metadata.json - размеры изображений, список классов, отображение лейблов

Данные файлы дальше используются на FastAPI-сервере

# Flower Classifier API

Сервер реализован на **FastAPI + Celery + Redis + PostgreSQL** с интеграцией Telegram-бота.

# Архитектура

## Технологический стек

* **FastAPI** — API-сервер
* **Celery** — асинхронная обработка задач
* **Redis** — брокер сообщений и backend результатов
* **PostgreSQL** — база данных
* **Docker / docker-compose** — контейнеризация
* **Telegram Bot API** — пользовательский интерфейс

---

# API (FastAPI + Celery)

## Основная логика работы

* `main.py`:

  * запускает FastAPI-приложение
  * инициализирует классификатор
  * запускает Telegram-бота
  * подключается к базе данных

* Все задачи по обработке изображений отправляются в очередь **Celery** и выполняются асинхронно.

* `tasks.py` (Celery Worker):

  * извлекает задачу из очереди
  * выполняет классификацию изображения
  * возвращает результат

---

## Redis + Celery

**Redis используется как:**

1. Брокер сообщений

   * принимает задачи от FastAPI
   * передаёт их Celery-воркеру

2. Backend результатов

   * хранит результаты выполнения задач

3. Кэш модели

   * сериализованная модель `FlowerClassifier` сохраняется в Redis (через `pickle`)
   * ускоряет повторную обработку без повторной загрузки модели

---

# Как происходит предсказание

1. Пользователь (через Telegram-бота) отправляет изображение цветка
2. FastAPI:

   * принимает фото
   * преобразует его в base64
   * формирует задачу Celery
3. Задача помещается в очередь Redis
4. Celery-воркер:

   * извлекает задачу
   * временно сохраняет изображение на диск
   * передаёт его в `FlowerClassifier.predict()`
5. Возвращается результат (топ-3 варианта с вероятностями)

# Telegram Bot

## Запуск

1. Откройте Telegram
2. Найдите бота: `@FloweyClassifierBot`
3. Нажмите `/start`
4. Для инструкции используйте `/help`

---

## Доступные действия

После запуска бот предлагает две кнопки:

### Определить цветок по фото

* Отправьте чёткое фото цветка
* Бот вернёт:

  * топ-3 варианта
  * точность предсказания
    
### Найти цветок по названию

* Введите часть названия (например: `роза`, `подсолнух`)
* Бот предложит список вариантов
* Выберите нужный
* Получите фото и описание

---

## Inline-поиск

Можно использовать бота прямо в любом чате:

```
@flower_classifier_bot роза
```

Бот предложит варианты в режиме реального времени.
При выборе варианта отображается фото и описание.

# PostgreSQL

База данных содержит две основные таблицы:

---

# `users`

Хранит информацию о пользователях Telegram.

| Поле             | Описание                   |
| ---------------- | -------------------------- |
| telegram_user_id | Уникальный ID пользователя |
| username         | Никнейм пользователя       |

---

# `interactions`

Фиксирует все пользовательские запросы.

| Поле       | Описание                                           |
| ---------- | -------------------------------------------------- |
| user_id    | Внешний ключ → `telegram_user_id`                  |
| query_type | Тип запроса                                        |
| query_text | Текст запроса (если есть)                          |
| flower_image      | Бинарные данные изображения (если отправлено фото) |

### Возможные значения `query_type`:

* `define_by_photo`
* `search_by_name`
* `search_by_name_inline`

---

# Методы работы с БД

* `get_user_by_telegram_id` — получить пользователя
* `create_user` — зарегистрировать пользователя
* `save_query` — сохранить взаимодействие
